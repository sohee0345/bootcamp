### 클래스 vs 인스턴스

- **클래스(class)**: 코드가 하드디스크에 저장만 되어 있는 상태, 즉 "설계도"다.
- **인스턴스(instance)**: 그 코드가 RAM(메모리) 위에 올라간 상태, 즉 설계도로 찍어낸 "실체"다.
- 함수는 하드 1개당 RAM에 1개만 올라가지만, 클래스는 하드 1개(설계도 1개)로 RAM에 N개(인스턴스 여러 개)를 만들 수 있다.

```python
class Person:
    def __init__(self, name):
        self.name = name
Person.name        # AttributeError -> 클래스 자체에는 인스턴스가 없어서 접근 불가
LEE = Person("이순신")
LEE.name            # '이순신' -> 인스턴스가 존재하므로 접근 가능
```

클래스를 다시 정의하면, 그 클래스로 만들었던 인스턴스도 새로 만들어야 한다(기존 인스턴스는 이전 설계도를 참조하고 있기 때문이다). 일반적인 네이밍 관례로 변수 선언은 명사, 함수(메소드) 선언은 동사로 짓는다. 그리고 `변수명()`처럼 괄호가 붙으면 그건 함수(메소드) 호출이다.

### `self`

`self`는 인스턴스 자기 자신을 가리킨다. 클래스 안에서 계속 기억하고 재사용해야 하는 값은 `self`(=객체)에 저장해두면, 매번 함수 호출 때마다 입력으로 넘기지 않아도 내부에서 직접 조작하고 변경할 수 있다.

- 변수를 굳이 기억할 필요가 없는 경우 → **함수**로 충분
- 변수를 계속 기억해야 하는 경우 → **클래스**가 필요 클래스 안에 정의하는 변수는 그 클래스의 메소드들이 실제로 사용할 변수만 최소한으로 두는 것이 원칙이다. 결국 클래스를 쓰는 이유는 "여러 메소드가 공유해서 써야 할 데이터를 한 곳에 저장해두기 위해서"다.

### 매직메소드 `__init__` — 생성자

인스턴스를 만드는 순간(`Person("이순신")`처럼 호출하는 순간) 자동으로 실행되는 함수이며, 입력 파라미터를 받을 수 있다.

```python
class Person:
    def __init__(self, name, age=0):   # 함수처럼 기본값도 지정 가능
        self.name = name
        self.age = age
LEE = Person("이순신")          # 기본값(age=0)으로 실행
KIM = Person("김유신", 45)      # 입력한 값(45)으로 실행
```

- 외부에서 `__init__`의 파라미터로 받은 변수는 **호출은 가능하지만 함부로 수정하면 설계 의도에서 벗어날 수 있고**,
- 인스턴스 내부에서 `self.xxx`로 선언한 변수는 **호출과 수정이 모두 자유롭게 가능하다**. 즉 클래스를 만들 때는 거의 항상 `__init__`(생성자)을 함께 정의해서, 인스턴스가 만들어질 때 필요한 초기 상태를 세팅해준다.

### 그 외 키워드로만 정리했던 개념들

**상속(inheritance)** — 부모 클래스의 속성과 메소드를 자식 클래스가 그대로 물려받는 것이다. 문법은 `class 자식클래스(부모클래스):` 형태다.

```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return f"{self.name}가 소리를 냅니다."
class Dog(Animal):        # Animal을 상속
    def speak(self):        # 부모 메소드를 재정의(오버라이딩)
        return f"{self.name}가 멍멍 짖습니다."
d = Dog("초코")
d.speak()   # '초코가 멍멍 짖습니다.'
```

**접근지정자(access modifier)** — 파이썬은 다른 언어처럼 강제적인 `private` 키워드는 없지만, 이름 앞에 언더스코어(`_`, `__`)를 붙여서 접근 범위에 대한 약속(컨벤션)을 표시한다.

```python
class Account:
    def __init__(self, balance):
        self.balance = balance          # public: 외부에서 자유롭게 접근
        self._note = "내부용 메모"        # protected 관례: 가급적 내부에서만 사용
        self.__pin = "1234"              # private 관례: 이름 맹글링으로 외부 접근을 어렵게 만듦
a = Account(1000)
a.balance     # 1000 (정상 접근)
a.__pin       # AttributeError (이름이 _Account__pin 으로 맹글링되어 직접 접근 불가)
```

**데코레이터(클래스에서)** — 4일차에서 본 함수 데코레이터와 같은 개념이지만, 클래스 안에서는 `@staticmethod`, `@classmethod`, `@property`처럼 메소드의 성격을 바꾸는 데 자주 쓰인다.

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius
    @property
    def area(self):              # 메소드를 속성처럼 호출 가능하게 만듦
        return 3.14 * self.radius ** 2
c = Circle(2)
c.area   # 12.56  (c.area() 가 아니라 괄호 없이 접근)
```

**매직메소드(magic method)** — `__init__`처럼 앞뒤에 언더스코어 두 개가 붙어서, 특정 상황에 파이썬이 자동으로 호출해주는 특수 메소드들이다.

```python
class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __str__(self):                     # print(인스턴스) 할 때 호출됨
        return f"({self.x}, {self.y})"
    def __add__(self, other):               # 인스턴스끼리 + 연산할 때 호출됨
        return Point(self.x + other.x, self.y + other.y)
p1, p2 = Point(1, 2), Point(3, 4)
print(p1)          # (1, 2)   -> __str__ 호출
print(p1 + p2)      # (4, 6)   -> __add__ 호출
```

**싱글톤 디자인 패턴(singleton)** — 프로그램 전체에서 인스턴스를 딱 하나만 만들어서 공유하도록 강제하는 설계 패턴이다. 설정값이나 DB 연결처럼 "여러 개가 있으면 오히려 문제가 되는" 대상에 사용한다.

```python
class Config:
    _instance = None   # 클래스 변수로 유일한 인스턴스를 저장
    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
a = Config()
b = Config()
a is b   # True -> 항상 같은 인스턴스를 가리킴
```
