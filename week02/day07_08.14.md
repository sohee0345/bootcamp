### 모듈·패키지와 Streamlit

이전 수업에서 Python 코드를 모듈과 패키지로 나누어 `import`하는 방법과 Streamlit의 화면 요소를 학습했다. 오늘은 함수, 클래스, Enum, Streamlit을 결합하여 챗봇과 가위바위보 프로그램을 역할별 파일로 분리했다.

``` python
from common.show import show_msg
from common.constants import ROLE
from common.history import init_history
from common.ai import get_msg_of_ai
```

> **핵심:** 파일을 역할별로 분리하고 필요한 기능만 가져와 하나의 프로그램으로 연결한다.

## 1. 모듈화

모듈화는 모든 코드를 하나의 파일에 작성하지 않고 기능과 책임에 따라 여러 파일로 나누어 관리하는 것이다.

``` text
chatbot/
  ├─ app.py                 화면 구성과 실행 흐름
  └─ common/
      ├─ ai.py              AI 응답 생성
      ├─ constants.py       역할 상수
      ├─ history.py         대화 이력 초기화·복원
      └─ show.py            메시지 출력·저장
```

역할을 분리하면 화면만 바꿀 때는 `app.py`, AI 응답 방식을 바꿀 때는 `ai.py`, 메시지 표시 방식을 바꿀 때는 `show.py`를 중심으로 수정할 수 있다.

### 1.1 절대 import와 상대 import

``` python
# app.py
from common.show import show_msg
from common.constants import ROLE

# common/ai.py
from .constants import ROLE
```

- `from common.show ...` → 패키지 경로를 적는 절대 import
- `from .constants ...` → 현재 패키지를 기준으로 가져오는 상대 import
- `.` → 현재 패키지를 의미

### 1.2 가위바위보 프로그램의 모듈화

가위바위보 실습도 역할을 나누었다.

``` text
main.py                       전체 게임 실행
game/
  ├─ constants.py             Enum과 승패 규칙
  ├─ inputs.py                사용자 입력과 검증
  ├─ prints.py                결과 출력
  └─ 가위바위보게임.py          게임 진행과 결과 구성
```

``` python
from game.constants import 게임종류
from game.prints import print_game_result
from game.가위바위보게임 import do_game

def 게임실행(game_type: 게임종류 = 게임종류.가위바위보):
    게임결과 = do_game() if game_type == 게임종류.가위바위보 else None
    if 게임결과:
        print_game_result(
            결과=게임결과["게임결과"],
            사용자_값=게임결과["사용자입력값"],
            컴퓨터_값=게임결과["컴퓨터입력값"],
        )

if __name__ == "__main__":
    게임실행()
```

> **오류 수정:** 실습의 파라미터 이름 `grame_type`은 `game_type`의 오타이므로 정리노트에서 바로잡았다.

## 2. Streamlit 대화 상태 관리

Streamlit은 사용자가 입력하거나 위젯을 조작하면 코드가 위에서부터 다시 실행될 수 있다. 다시 실행되어도 유지할 대화 기록은 `st.session_state`에 저장한다.

### 2.1 대화 이력 초기화와 복원

``` python
import streamlit as st

def init_history() -> None:
    if "history" not in st.session_state:
        st.session_state.history = []

    for history in st.session_state.history:
        show_msg(**history, is_history=True)
```

- 키가 없을 때만 빈 리스트 생성
- 저장된 이력을 순회하며 화면에 다시 표시
- `is_history=True`로 복원 중인 메시지를 다시 저장하지 않음

### 2.2 역할을 Enum으로 관리

``` python
import enum

class ROLE(enum.Enum):
    user = enum.auto()
    assistant = enum.auto()
```

문자열을 반복해서 직접 적는 대신 Enum으로 사용자와 AI 역할을 구분했다. `role.name`을 사용하면 `user`, `assistant` 문자열을 얻을 수 있다.

### 2.3 메시지 표시와 저장

``` python
def show_msg(role: ROLE, msg: str, is_history=False) -> None:
    assert isinstance(role, ROLE), "정상적인 코드가 아닙니다."

    with st.chat_message(role.name):
        st.markdown(msg)

    if not is_history:
        st.session_state.history.append({
            "role": role,
            "msg": msg,
        })
```

- `st.chat_message(role.name)` → 역할에 맞는 채팅 영역 생성
- `st.markdown(msg)` → 메시지 표시
- 새 메시지만 `history`에 추가
- 복원 중인 과거 메시지는 중복 저장하지 않음

## 3. Streamlit 챗봇 UI

`app.py`는 화면과 전체 실행 순서를 담당한다.

``` python
import streamlit as st

from common.show import show_msg
from common.constants import ROLE
from common.history import init_history
from common.ai import get_msg_of_ai

st.title("ChatBot Service")
init_history()

user_input = st.chat_input("메시지 입력해주세요.")

if user_input:
    show_msg(role=ROLE.user, msg=user_input)
    response = get_msg_of_ai(user_input)
    show_msg(role=ROLE.assistant, msg=response)
```

``` text
앱 실행
  ↓
기존 대화 이력 초기화·복원
  ↓
st.chat_input()으로 사용자 입력
  ↓
사용자 메시지 표시·저장
  ↓
AI 응답 함수 호출
  ↓
AI 메시지 표시·저장
```

### 3.1 `st.chat_input()`과 `st.chat_message()`

``` python
user_input = st.chat_input("메시지를 입력하세요")

with st.chat_message("user"):
    st.markdown(user_input)
```

- `st.chat_input()` → 사용자 메시지 입력창
- `st.chat_message("user")` → 사용자 메시지 영역
- `st.chat_message("assistant")` → AI 메시지 영역

## 4. LLM Chat API 호출

실습에서는 `.env`의 환경 변수를 불러오고 Groq 클라이언트로 Chat API를 호출했다.

### 4.1 클라이언트 생성과 캐싱

``` python
import streamlit as st
from groq import Groq
from dotenv import load_dotenv

@st.cache_resource
def get_client():
    load_dotenv()
    return Groq()
```

- `load_dotenv()` → `.env` 파일 값을 환경 변수로 불러옴
- `Groq()` → API 통신에 사용할 클라이언트 생성
- `@st.cache_resource` → 다시 실행될 때마다 클라이언트를 새로 만들지 않고 재사용

### 4.2 대화 이력을 API 형식으로 변환

``` python
messages = [
    {
        "role": history["role"].name,
        "content": history["msg"],
    }
    for history in st.session_state.history
]
```

Streamlit 내부에서는 `role`, `msg`를 사용했지만 API에 전달할 때는 `role`, `content` 구조로 바꿨다.

``` python
response = client.chat.completions.create(
    messages=messages,
    model="openai/gpt-oss-120b",
)

answer = response.choices[0].message.content
```

### 4.3 실습 코드의 메시지 중복 주의

실습 `app.py`는 사용자 메시지를 `show_msg()`로 먼저 이력에 저장한 뒤 `get_msg_of_ai(user_input)`을 호출한다. 그런데 `get_msg_of_ai()`는 저장된 이력으로 `messages`를 만든 후 같은 `user_input`을 한 번 더 추가한다.

따라서 API 요청에는 최신 사용자 메시지가 두 번 포함될 수 있다. 한 가지 방식만 선택해야 한다.

``` python
# 사용자 메시지가 이미 history에 저장된 경우
messages = [
    {
        "role": history["role"].name,
        "content": history["msg"],
    }
    for history in st.session_state.history
]

# 같은 user_input을 다시 append하지 않음
```

> **핵심:** 화면에 표시할 이력과 API에 보낼 이력의 저장 시점을 정해 같은 사용자 메시지가 중복되지 않도록 한다.

## 5. 역할 분리의 효과

| 변경 사항 | 주로 수정할 파일 |
| --- | --- |
| 제목·입력창·화면 흐름 | `app.py` |
| 메시지 표시와 저장 방식 | `show.py` |
| 이력 초기화와 복원 | `history.py` |
| 사용자·AI 역할 상수 | `constants.py` |
| 모델과 API 호출 방식 | `ai.py` |

기능별 책임이 분명하면 코드를 찾고 수정하기 쉬우며, 같은 기능을 다른 곳에서도 재사용할 수 있다.

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| 모듈화 | 기능과 책임에 따라 코드를 여러 파일로 분리 |
| `session_state` | Streamlit 재실행 사이에 유지할 상태 저장 |
| 채팅 이력 | 사용자와 AI의 역할·메시지를 순서대로 저장한 데이터 |
| `cache_resource` | 클라이언트 같은 자원을 재사용하도록 캐싱 |
| Chat API | 역할과 내용으로 구성한 메시지를 모델에 전달하고 응답 수신 |
| UI·로직 분리 | 화면과 비즈니스 로직을 별도 모듈로 관리 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `from module import name` | 다른 모듈의 기능 가져오기 |
| `st.session_state.history = []` | 대화 이력 초기화 |
| `st.chat_input()` | 사용자 메시지 입력 |
| `st.chat_message(role)` | 역할별 메시지 영역 표시 |
| `@st.cache_resource` | API 클라이언트 자원 캐싱 |
| `client.chat.completions.create(...)` | Chat API 호출 |
| `response.choices[0].message.content` | 응답 메시지 내용 추출 |

### ⭐ 오늘의 핵심

- **모듈화:** UI, 이력, 메시지 출력, 상수, AI 호출을 역할별 파일로 분리한다.
- **상태 관리:** Streamlit 재실행 뒤에도 필요한 대화 이력은 `session_state`에 저장한다.
- **채팅 흐름:** 입력 → 사용자 메시지 저장 → API 호출 → AI 응답 저장 → 화면 출력 순서로 동작한다.
- **중복 방지:** 화면 이력과 API 메시지의 저장 시점을 조정해 같은 입력을 두 번 보내지 않는다.
