## 1. Docker로 MySQL 서버 실행

`docker-compose.yml`은 MySQL 이미지 버전, 포트, 계정, 비밀번호, 데이터베이스 이름 등 컨테이너 설정을 정의하는 파일이다.

``` text
docker-compose.yml 작성
  ↓
docker compose up -d
  ↓
MySQL 컨테이너 생성·실행
  ↓
Docker Desktop에서 Running 상태 확인
```

- `docker compose up -d` → 설정을 기준으로 컨테이너를 생성하고 백그라운드에서 실행
- `docker compose down` → Compose로 실행한 컨테이너를 중지하고 제거
- `-d` → 터미널을 계속 점유하지 않는 백그라운드 실행

실습 화면에서는 Docker Desktop의 `server` 컨테이너가 실행 중인 것을 확인했다.

## 2. DBeaver로 MySQL 접속

DBeaver는 MySQL 서버에 접속해 SQL을 작성·실행하고 결과와 테이블 구조를 확인하는 GUI 클라이언트이다.

``` text
New Connection
  ↓
MySQL 선택
  ↓
Host·Port·Username·Password 입력
  ↓
Test Connection
  ↓
연결 저장
```

실습 화면에서는 다음 정보를 사용했다.

- Host → `localhost`
- Port → `3306`
- Username → `root`

![[04 실습파일/week03/day09/스크린샷 2026-08-19 125030.png]]

`allowPublicKeyRetrieval` 오류가 발생하면 `Edit Connection → Driver properties`에서 해당 값을 `True`로 변경하고 다시 `Test Connection`을 실행한다. 연결 이름은 `계정명@MySQL` 형식으로 정리할 수 있다.

SQL은 `;`으로 문장을 구분한다. 실행할 문장 안에 커서를 두고 `Ctrl+Enter`를 누르면 해당 SQL을 실행할 수 있다.

## 3. 데이터베이스와 테이블 생성

### 3.1 데이터베이스 생성과 선택

``` sql
SHOW DATABASES;

CREATE DATABASE IF NOT EXISTS mysql_ddl_practice
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_unicode_ci;

USE mysql_ddl_practice;
```

- `SHOW DATABASES` → 데이터베이스 목록 확인
- `CREATE DATABASE IF NOT EXISTS` → 같은 이름이 없을 때 데이터베이스 생성
- `utf8mb4` → 한글·특수문자·이모지를 저장할 수 있는 문자 집합
- `USE` → 이후 SQL이 실행될 데이터베이스 선택

### 3.2 테이블 생성과 구조 확인

``` sql
DROP TABLE IF EXISTS datatype_examples;

CREATE TABLE datatype_examples (
    example_id INT AUTO_INCREMENT COMMENT '자동 증가 기본키',
    student_name VARCHAR(50) NOT NULL COMMENT '수강생 이름',
    age TINYINT UNSIGNED COMMENT '수강생 나이',
    tuition DECIMAL(10, 2) COMMENT '수강료',
    is_active BOOLEAN DEFAULT TRUE COMMENT '활성 상태',
    joined_on DATE DEFAULT (CURRENT_DATE) COMMENT '가입일',
    last_login_at DATETIME COMMENT '마지막 로그인 시각',
    profile JSON COMMENT '추가 프로필',
    memo TEXT COMMENT '메모',
    PRIMARY KEY (example_id)
);
```

``` sql
SHOW TABLES;
DESCRIBE datatype_examples;
SHOW FULL COLUMNS FROM datatype_examples;
```

- `DROP TABLE IF EXISTS` → 테이블이 있을 때만 삭제
- `CREATE TABLE` → 컬럼과 규칙을 지정해 테이블 생성
- `DESCRIBE` → 컬럼 구조 확인
- `SHOW FULL COLUMNS` → 컬럼의 상세 정보와 주석 확인

### 3.3 주요 데이터 타입

| 데이터 타입 | 저장 내용 |
| --- | --- |
| `INT` | 정수 |
| `TINYINT UNSIGNED` | 음수가 없는 작은 범위의 정수 |
| `DECIMAL(10, 2)` | 전체 자릿수와 소수 자릿수가 정해진 수 |
| `BOOLEAN` | 참·거짓 값 |
| `VARCHAR(n)` | 최대 `n`문자의 가변 길이 문자열 |
| `TEXT` | 긴 문자열 |
| `DATE` | 날짜 |
| `DATETIME` | 날짜와 시간 |
| `JSON` | JSON 형식 데이터 |
| `ENUM(...)` | 미리 지정한 값 중 하나 |

### 3.4 `ALTER TABLE`

이미 만든 테이블의 구조는 `ALTER TABLE`로 변경한다.

``` sql
ALTER TABLE datatype_examples
ADD COLUMN email VARCHAR(120) COMMENT '수강생 이메일';

ALTER TABLE datatype_examples
MODIFY COLUMN memo VARCHAR(500) COMMENT '메모';

ALTER TABLE datatype_examples
DROP COLUMN email;
```

- `ADD COLUMN` → 컬럼 추가
- `MODIFY COLUMN` → 컬럼 타입·길이·주석 등 변경
- `DROP COLUMN` → 컬럼 삭제

## 4. 데이터 추가와 조회

``` sql
INSERT INTO students (name, email, birth_date, phone)
VALUES
    ('김민준', 'minjun@example.com', '2001-03-12', '010-1111-1111'),
    ('이서연', 'seoyeon@example.com', '2000-07-22', '010-2222-2222');

SELECT *
FROM students;
```

- `INSERT INTO` → 지정한 컬럼에 행 추가
- `VALUES` → 추가할 실제 값 작성
- `SELECT` → 테이블 데이터 조회
- 여러 괄호를 쉼표로 나열 → 여러 행을 한 문장으로 추가

`AUTO_INCREMENT` 컬럼은 `INSERT`에서 생략하면 행이 추가될 때 자동으로 값이 증가한다.

``` sql
INSERT INTO userdb (name, addr)
VALUES
    ('홍길동', '서울시 강남구'),
    ('신사임당', '부산 해운대구');
```

실행 결과:

``` text
id | name     | addr
1  | 홍길동    | 서울시 강남구
2  | 신사임당  | 부산 해운대구
```

## 5. 제약조건

제약조건은 잘못된 데이터가 저장되지 않도록 컬럼과 테이블에 적용하는 규칙이다.

| 제약조건 | 역할 |
| --- | --- |
| `NOT NULL` | 값 생략 금지 |
| `UNIQUE` | 중복 값 금지 |
| `CHECK` | 지정한 조건을 만족하는 값만 허용 |
| `DEFAULT` | 값 생략 시 사용할 기본값 |
| `PRIMARY KEY` | 각 행을 고유하게 식별 |
| `FOREIGN KEY` | 다른 테이블의 키를 참조 |

``` sql
CREATE TABLE courses (
    course_id INT AUTO_INCREMENT,
    title VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) NOT NULL DEFAULT 0 CHECK (price >= 0),
    level ENUM('beginner', 'intermediate', 'advanced') NOT NULL,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    PRIMARY KEY (course_id)
);
```

실습에서는 다음 위반 사례를 하나씩 실행해 확인하도록 구성했다.

- 이름 누락 → `NOT NULL` 위반
- 같은 이메일 추가 → `UNIQUE` 위반
- 음수 가격 추가 → `CHECK (price >= 0)` 위반

## 6. 기본키와 외래키로 테이블 연결

### 6.1 1:N 관계

한 수강생은 여러 수강 신청을 할 수 있고, 한 수강 신청에는 여러 결제가 연결될 수 있다.

``` text
students 1 ── N enrollments
courses  1 ── N enrollments
enrollments 1 ── N payments
```

### 6.2 N:M 관계와 연결 테이블

수강생 한 명이 여러 강의를 신청하고 강의 하나에도 여러 수강생이 참여하므로 `students`와 `courses`는 N:M 관계이다. 이를 `enrollments` 연결 테이블로 나눈다.

``` sql
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT,
    student_id INT NOT NULL,
    course_id INT NOT NULL,
    enrolled_at DATE NOT NULL DEFAULT (CURRENT_DATE),
    status ENUM('enrolled', 'completed', 'canceled')
        NOT NULL DEFAULT 'enrolled',
    score DECIMAL(5, 2) CHECK (score BETWEEN 0 AND 100),
    PRIMARY KEY (enrollment_id),
    UNIQUE KEY uq_enrollments_student_course (student_id, course_id),
    CONSTRAINT fk_enrollments_student
        FOREIGN KEY (student_id) REFERENCES students(student_id)
        ON DELETE CASCADE,
    CONSTRAINT fk_enrollments_course
        FOREIGN KEY (course_id) REFERENCES courses(course_id)
        ON DELETE RESTRICT
);
```

- 복합 `UNIQUE KEY` → 같은 학생이 같은 강의를 중복 신청하지 못하게 함
- `ON DELETE CASCADE` → 부모 행 삭제 시 관련 자식 행도 삭제
- `ON DELETE RESTRICT` → 참조 중인 자식 행이 있으면 부모 행 삭제 제한
- 부모 테이블의 데이터를 먼저 추가한 뒤 이를 참조하는 자식 데이터를 추가
- 테이블 삭제는 반대로 자식 테이블부터 진행

### 6.3 JOIN으로 관계 데이터 조회

``` sql
SELECT
    s.name AS student_name,
    c.title AS course_title,
    e.status,
    e.score,
    p.amount,
    p.method
FROM enrollments e
JOIN students s ON e.student_id = s.student_id
JOIN courses c ON e.course_id = c.course_id
LEFT JOIN payments p ON e.enrollment_id = p.enrollment_id
ORDER BY s.name, c.title;
```

- 별칭 `s`, `c`, `e`, `p` → 긴 테이블 이름을 짧게 사용
- `JOIN ... ON` → 키가 일치하는 관련 행 연결
- `LEFT JOIN` → 왼쪽 테이블의 행을 유지하며 결제 정보 연결
- `AS` → 결과 컬럼 이름 지정
- `ORDER BY` → 결과 정렬

``` text
Docker Compose로 MySQL 서버 실행
  ↓

  ↓
데이터베이스 생성·선택
  ↓
데이터 타입과 제약조건을 지정해 테이블 생성
  ↓
INSERT로 데이터 추가 → SELECT로 조회
  ↓
기본키·외래키로 1:N 관계 구성
  ↓
연결 테이블로 N:M 관계 해소
  ↓
JOIN으로 여러 테이블의 데이터 조회
```
