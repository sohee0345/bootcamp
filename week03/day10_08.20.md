### 1. 기본키 (Primary Key)

`PRIMARY KEY`는 테이블에서 **각 행(row)을 고유하게 구분하는 값**이다.

기본키로 지정된 컬럼은 다음 조건을 만족해야 한다.

* `UNIQUE` → 값이 중복될 수 없음
* `NOT NULL` → 빈 값(`NULL`)이 들어갈 수 없음

예를 들어 사용자 테이블에서 `id`를 기본키로 사용한다면, 각 사용자는 서로 다른 `id`를 가져야 한다.

> **Primary Key = 중복 X + NULL X + 데이터를 구별하는 식별자**

### 2. Docker Desktop에서 MySQL 컨테이너 터미널 접속

Docker Desktop의 **Exec 탭**을 이용하면 실행 중인 MySQL 컨테이너 내부에서 직접 명령어를 실행할 수 있다.

### 3. `classicmodels` 예제 데이터베이스 조회

SQL 조회 연습을 위해 `classicmodels` 예제 데이터베이스를 사용했다.

```sql
USE classicmodels;

SHOW TABLES;
```

`SHOW TABLES`를 실행하면 현재 데이터베이스에 존재하는 테이블 목록을 확인할 수 있다.

고객 중 국가가 `USA`인 데이터를 조회하고, 신용한도가 높은 순서대로 10명만 가져온다.

```sql
SELECT
    customerName,
    phone,
    country,
    creditLimit
FROM customers
WHERE country = 'USA'
ORDER BY creditLimit DESC
LIMIT 10;
```

각 SQL의 역할:

* `SELECT` → 조회할 컬럼 선택
* `FROM` → 조회할 테이블 선택
* `WHERE` → 조건에 맞는 데이터만 선택
* `ORDER BY` → 데이터 정렬
* `DESC` → 내림차순
* `ASC` → 오름차순이며 생략 시 기본값
* `LIMIT 10` → 결과를 앞에서 10개까지만 조회

```text
ORDER BY creditLimit DESC
→ creditLimit이 큰 값부터 작은 값 순서

ORDER BY creditLimit ASC
→ creditLimit이 작은 값부터 큰 값 순서
```

### 3.1 `JOIN`으로 여러 테이블 연결하기

`JOIN`은 **서로 다른 테이블을 공통된 컬럼을 기준으로 연결해서 조회**할 때 사용한다.

이번에는 `customers`와 `orders` 테이블을 이용해 **주문을 가장 많이 한 고객 3명**을 조회했다.

먼저 고객별 주문 횟수를 계산한다.

```sql
SELECT
    COUNT(orderNumber) AS cnt,
    customerNumber
FROM orders
GROUP BY customerNumber
ORDER BY cnt DESC
LIMIT 3;
```

* `COUNT(orderNumber)` → 주문 개수 계산
* `AS cnt` → 계산 결과에 `cnt`라는 별명(alias) 지정
* `GROUP BY customerNumber` → 같은 고객 번호끼리 묶기
* `ORDER BY cnt DESC` → 주문 횟수가 많은 순서대로 정렬
* `LIMIT 3` → 상위 3명만 조회

이 결과를 **서브쿼리**로 만든 뒤 `customers` 테이블과 연결한다.

```sql
SELECT
    t1.customerName,
    t1.phone,
    t1.country,
    t1.creditLimit,
    t2.cnt
FROM customers t1
JOIN (
    SELECT
        COUNT(orderNumber) AS cnt,
        customerNumber
    FROM orders
    GROUP BY customerNumber
    ORDER BY cnt DESC
    LIMIT 3
) t2
ON t1.customerNumber = t2.customerNumber;
```

```text
t1 → customers 테이블의 별명
t2 → 서브쿼리 결과의 별명
```

`t1`, `t2`처럼 테이블에 별명(alias)을 붙이면 같은 쿼리 안에서 **어느 테이블의 컬럼인지 쉽게 구분**할 수 있다.

```sql
ON t1.customerNumber = t2.customerNumber
```
> 테이블에서 `customerNumber`가 같은 데이터를 서로 연결한다는 의미이다.

> **서브쿼리(Subquery) = SQL문 안에 들어가는 또 다른 SQL문**

> **JOIN + 서브쿼리 = 먼저 필요한 결과를 계산한 뒤 다른 테이블과 다시 연결**

### 3.2 고객별 주문 총액 구하기

`orderdetails` 테이블에서 하나의 주문 상품에 대한 금액을 계산한다.

```sql
SELECT
    quantityOrdered * priceEach AS totalPrice,
    orderNumber
FROM orderdetails
ORDER BY totalPrice DESC;
```

주문 금액 계산:

```text
주문 수량 × 상품 가격 = 주문 금액
```

```sql
quantityOrdered * priceEach
```
> 각 주문 상세 데이터의 금액을 계산한다.

그다음 `orders` 테이블과 연결해서 **고객별 전체 주문 금액**을 구한다.

```sql
SELECT
    t1.customerNumber,
    SUM(t2.totalPrice) AS totalPriceByCustom
FROM orders t1
JOIN (
    SELECT
        quantityOrdered * priceEach AS totalPrice,
        orderNumber
    FROM orderdetails
) t2
ON t1.orderNumber = t2.orderNumber
GROUP BY customerNumber
ORDER BY totalPriceByCustom DESC;
```

* `SUM()` → 같은 그룹에 속한 값들의 합계
* `GROUP BY customerNumber` → 고객별로 묶기
* `ORDER BY totalPriceByCustom DESC` → 총 구매 금액이 큰 고객부터 정렬

전체 흐름:

```text
orderdetails
→ 주문별 상품 금액 계산
        ↓
orders와 JOIN
        ↓
고객 번호 확인
        ↓
GROUP BY customerNumber
        ↓
SUM()
        ↓
고객별 총 주문 금액 계산
```

이렇게 조회하면 주문을 하지 않은 고객은 결과에서 빠지고, 실제 주문이 있는 고객의 총 구매 금액을 확인할 수 있다.

### 3.3 총 구매 금액이 가장 큰 고객 3명 조회

앞에서 만든 쿼리를 한 번 더 `customers` 테이블과 연결하면 **총 구매 금액이 가장 큰 고객 3명의 상세 정보**를 조회할 수 있다.

```sql
SELECT
    t1.customerName,
    t1.phone,
    t1.country,
    t1.creditLimit,
    t2.totalPriceByCustom
FROM customers t1
JOIN (
    SELECT
        t1.customerNumber,
        SUM(t2.totalPrice) AS totalPriceByCustom
    FROM orders t1
    JOIN (
        SELECT
            quantityOrdered * priceEach AS totalPrice,
            orderNumber
        FROM orderdetails
    ) t2
    ON t1.orderNumber = t2.orderNumber
    GROUP BY customerNumber
    ORDER BY totalPriceByCustom DESC
    LIMIT 3
) t2
ON t1.customerNumber = t2.customerNumber;
```

전체 과정:

```text
orderdetails
→ 주문 상품별 금액 계산
        ↓
orders와 JOIN
→ 고객별 총 구매 금액 계산
        ↓
구매 금액이 큰 상위 3명 선택
        ↓
customers와 JOIN
        ↓
고객 이름 / 전화번호 / 국가 / 신용한도 / 총 구매액 조회
```

결과:

| customerName                 | phone        | country   | creditLimit | totalPriceByCustom |
| ---------------------------- | ------------ | --------- | ----------: | -----------------: |
| Euro+ Shopping Channel       | 91 555 94 44 | Spain     |     227,600 |         820,689.54 |
| Mini Gifts Distributors Ltd. | 4155551450   | USA       |     210,500 |         591,827.34 |
| Australian Collectors, Co.   | 03 9520 4555 | Australia |     117,300 |         180,585.07 |

> 복잡한 SQL도 **작은 쿼리부터 하나씩 만든 다음 JOIN과 서브쿼리로 연결**하면 이해하기 쉽다.

### 5. Python에서 MySQL 연결하기

Python에서 MySQL에 접속하려면 다음 정보가 필요하다.

* **Driver** → Python과 MySQL을 연결하는 라이브러리 (`pymysql`)
* **계정정보** → ID, Password
* **서버정보** → IP(Host), Port
* **데이터베이스명** → 사용할 Database

```python
import pymysql

DB_CONFIG = {
    # MySQL 서버정보
    "host": "localhost",
    "port": 3306,

    # 계정정보
    "user": "root",
    "password": "root1234",

    # 데이터베이스명
    "database": "classicmodels"
}
```

### 5.1 커넥션(Connection) 객체 생성

`pymysql.connect()`를 이용하면 Python과 MySQL 서버를 연결할 수 있다.

```python
with pymysql.connect(**DB_CONFIG) as conn:

    # 커넥션 객체로 실행할 커서 생성
    with conn.cursor() as cur:

        # SQL 명령어를 MySQL 서버로 전달
        cur.execute("""
        SHOW TABLES;
        """)

        # MySQL 실행 결과 가져오기
        results = cur.fetchall()

results
```

결과 예시:

```python
(
    ('customers',),
    ('employees',),
    ('offices',),
    ('orderdetails',),
    ('orders',),
    ('payments',),
    ('productlines',),
    ('products',)
)
```

각 객체의 역할:

```text
conn
→ Python과 MySQL의 연결을 담당하는 Connection 객체

cur
→ SQL을 MySQL에 전달하고 결과를 가져오는 Cursor 객체

execute()
→ SQL 실행

fetchall()
→ 조회된 결과 전체 가져오기
```

### 5.2 `with`문을 사용하는 이유

Connection과 Cursor는 사용이 끝나면 닫아줘야 하는 자원이다.

```python
with pymysql.connect(**DB_CONFIG) as conn:
    with conn.cursor() as cur:
        ...
```

`with`문을 사용하면 블록의 실행이 끝났을 때 사용한 자원을 자동으로 정리해준다.

따라서 연결을 직접 닫는 것을 깜빡하는 실수를 줄일 수 있다.

> **Connection = MySQL과 연결**

> **Cursor = 연결된 MySQL에 SQL을 전달**

### 6. `.env`로 계정정보 관리하기

DB 비밀번호처럼 중요한 정보를 Python 코드에 직접 작성하면 GitHub에 코드가 올라갈 때 같이 공개될 위험이 있다.

따라서 중요한 정보는 `.env` 파일에 따로 저장한다.

Python에서는 `os.getenv()`를 이용해서 환경변수를 가져올 수 있다.

```python
import pymysql
import os

DB_CONFIG = {
    # MySQL 서버정보
    "host": os.getenv("host"),
    "port": int(os.getenv("port")),

    # 계정정보
    "user": os.getenv("user"),
    "password": os.getenv("password"),

    # 데이터베이스명
    "database": os.getenv("database")
}
```

`os.getenv()`는 **환경변수에서 해당 이름의 값을 가져오는 함수**이다.

하지만 `.env` 파일을 만들었다고 해서 `os.getenv()`가 자동으로 파일 내용을 읽어오는 것은 아니다.

### 6.1 `load_dotenv()`

`.env` 파일의 값을 환경변수로 등록하기 위해 `python-dotenv`의 `load_dotenv()`를 사용한다.

```python
from dotenv import load_dotenv

# .env에 작성된 데이터를 환경변수로 등록
load_dotenv()
```

흐름:

```text
.env 파일
   ↓
load_dotenv()
   ↓
환경변수에 등록
   ↓
os.getenv()
   ↓
Python 코드에서 사용
```

`.env` 파일을 새로 만들거나 수정했다면 **노트북의 커널을 재시작(Restart)**해야 변경 사항이 반영되는 경우가 있으므로 함께 기억해둔다.

> **`.env` = 비밀번호 같은 중요한 정보를 코드와 분리해서 관리**

### 7. 커넥션 재사용 — Singleton

매번 MySQL에 연결하는 코드를 반복해서 작성하지 않고, 한 번 생성한 객체를 계속 사용할 수 있도록 `connections.py`에 `MySQLDB` 클래스를 만들었다.

```python
# connections.py

import pymysql

class Singleton(type):

    _instances = {}

    def __call__(cls, *args, **kwargs):

        if cls not in cls._instances:
            cls._instances[cls] = super(Singleton, cls).__call__(
                *args, **kwargs
            )

        return cls._instances[cls]


class MySQLDB(metaclass=Singleton):

    def __init__(self, DB_CONFIG: dict) -> None:

        self.conn = pymysql.connect(
            **DB_CONFIG,
            charset="utf8mb4",
            cursorclass=pymysql.cursors.DictCursor
        )

    def __call__(self, p_query: str) -> dict:

        with self.conn.cursor() as cur:

            # SQL 명령어 실행
            cur.execute(p_query)

            # 결과 반환
            return cur.fetchall()
```

`charset="utf8mb4"`는 한글을 포함한 문자를 처리하기 위한 문자 인코딩 설정이다.

```python
cursorclass=pymysql.cursors.DictCursor
```
> 설정하면 조회 결과를 **딕셔너리 형태**로 받을 수 있다.

### 7.1 Singleton이란?

Singleton은 **프로그램에서 특정 클래스의 객체를 하나만 만들어서 계속 재사용하는 방식**이다.

```text
MySQLDB(DB_CONFIG)
        ↓
처음 호출
→ 새로운 객체 생성

MySQLDB(DB_CONFIG)
        ↓
다시 호출
→ 기존 객체 재사용
```

`Singleton` 클래스의 `_instances`에 이미 생성한 객체를 저장한다.

```python
_instances = {}
```

객체를 생성하려고 할 때 기존 객체가 있는지 확인한다.

```python
if cls not in cls._instances:
```

없으면 새로 만들고, 이미 존재하면 저장되어 있는 객체를 반환한다.

> **Singleton = 객체를 여러 번 새로 만들지 않고 하나의 객체를 재사용**

### 7.2 `MySQLDB` 사용하기

Notebook에서는 다음과 같이 불러온다.

```python
from connections import MySQLDB

mysqldb = MySQLDB(DB_CONFIG)
```

이후 `mysqldb`를 함수처럼 호출하여 SQL을 실행할 수 있다.

```python
mysqldb("SELECT * FROM customers;")
```

이것이 가능한 이유는 `MySQLDB` 클래스에 `__call__()` 메소드가 정의되어 있기 때문이다.

```python
def __call__(self, p_query: str) -> dict:
```

`__call__()`이 정의된 객체는 **함수처럼 호출**할 수 있다.

```python
mysqldb(...)
```

전체 흐름:

```text
DB_CONFIG
    ↓
MySQLDB(DB_CONFIG)
    ↓
MySQL Connection 생성
    ↓
mysqldb 객체
    ↓
mysqldb("SQL")
    ↓
__call__() 실행
    ↓
Cursor 생성
    ↓
SQL 실행
    ↓
fetchall()
    ↓
결과 반환
```

### SQL 기본

| 개념             | 의미                 |
| -------------- | ------------------ |
| `PRIMARY KEY`  | 각 행을 고유하게 구별하는 기본키 |

### SQL 집계 · 테이블 연결

| 개념                 | 의미                     |
| ------------------ | ---------------------- |
| `COUNT()`          | 데이터 개수 계산              |

| 서브쿼리               | SQL문 안에 작성하는 또 다른 SQL문 |
| Alias (`t1`, `t2`) | 테이블이나 결과에 붙이는 별명       |

| 개념                  | 의미                        |
| ------------------- | ------------------------- |
| `pymysql`           | Python과 MySQL을 연결하는 라이브러리 |

| Cursor (`cur`)      | SQL을 전달하고 결과를 가져오는 객체     |
| `execute()`         | SQL 실행                    |
| `fetchall()`        | 조회 결과 전체 가져오기             |

| --------------- | ------------------------ |
| Docker Exec     | 컨테이너 내부에서 직접 명령어 실행      |
| `uv sync`       | 기존 프로젝트 환경에 맞춰 설치·동기화    |
| `uv init`       | 새로운 Python 프로젝트 생성       |
| `.env`          | 비밀번호·계정정보 등을 코드와 분리해서 관리 |
| `load_dotenv()` | `.env` 내용을 환경변수로 등록      |
| `os.getenv()`   | 환경변수 값 가져오기              |
