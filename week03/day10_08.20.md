### 기본키(Primary Key)

`primary키 = 기본키`. 각 행(row)을 고유하게 구분하는 값으로, 반드시 `unique`(중복 불가)해야 하고 `not null`(빈 값 불가)이어야 한다. `id`는 각 사용자를 유일하게 식별하는 값이어야 하기 때문이다.

### `classicmodels` 예제 데이터베이스로 조회 연습

```sql
use classicmodels;
show tables;

select
    customerName
    , phone
    , country
    , creditLimit
from customers
where country = 'USA'
order by creditLimit desc # desc = 내림차순 정렬
limit 10;
```

`order by`로 정렬 기준 컬럼을 지정할 수 있는데, `desc`를 붙이면 내림차순(큰 값 → 작은 값), 아무것도 안 붙이면 기본값인 오름차순(`asc`)으로 정렬된다. `limit 10`은 결과를 앞에서 10개까지만 가져오라는 뜻이다.

### `join`으로 여러 테이블 엮어서 조회하기

고객(`customers`) 테이블과 주문(`orders`) 테이블을 엮어서 "주문을 가장 많이 한 고객 3명"을 찾아내는 쿼리를 단계별로 만들어봤다.

```sql
select
    count(orderNumber) as cnt
    , customerNumber
from orders
group by customerNumber
order by cnt desc
limit 3;
```

```sql
SELECT
    t1.customerName
    , t1.phone
    , t1.country
    , t1.creditLimit
    , t2.cnt
from customers t1
join (
    select
        count(orderNumber) as cnt
        , customerNumber
    from orders
    group by customerNumber
    order by cnt desc
    limit 3
) t2
on t1.customerNumber = t2.customerNumber
;
```

여기서 배운 핵심은 `join` 안에 서브쿼리(괄호로 감싼 또 다른 `select` 문)를 넣어서 "먼저 집계한 결과"를 만든 다음, 그 결과를 원래 테이블과 다시 연결할 수 있다는 점이다. `t1`, `t2`는 테이블에 붙인 별명(alias)으로, 같은 쿼리 안에서 어느 테이블의 컬럼인지 구분하기 위해 사용한다.

### 고객별 주문 총액 구하기

```sql
select
    quantityOrdered * priceEach as totalPrice
    , orderNumber
from orderdetails
order by totalPrice desc;
```

```sql
select
    t2.customerNumber                           # 고객 식별자
    , sum(t2.totalPrice) as totalPriceByCustom  # 고객별 총 합계 금액
from orders t1
join (
    select
        quantityOrdered * priceEach as totalPrice
        , orderNumber
    from orderdetails
) t2
on t1.orderNumber = t2.orderNumber
group by customerNumber
order by totalPriceByCustom desc
;
```

`sum()`으로 그룹별 합계를, `group by`로 어떤 기준(고객 번호)으로 묶을지를 지정한다. 여기까지 오면 "주문 안 한 고객은 빠지고, 주문 금액이 큰 순서대로 고객 번호와 총액만" 나오게 된다.

### 최종 쿼리: 가장 많은 금액을 사용한 고객 3명의 정보 불러오기

```sql
SELECT
    t2.customerName
    , t2.phone
    , t2.country
    , t2.creditLimit
    , t2.totalPriceByCustom
from customers t1
join (
    select
        t1.customerNumber                          # 고객 식별자
        , sum(t2.totalPrice) as totalPriceByCustom  # 고객별 총 합계 금액
    from orders t1
    join (
        select
            quantityOrdered * priceEach as totalPrice
            , orderNumber
        from orderdetails
    ) t2
    on t1.orderNumber = t2.orderNumber
    group by customerNumber
    order by totalPriceByCustom desc
    limit 3
) t2
on t1.customerNumber = t2.customerNumber
;
```

지금까지 만든 서브쿼리를 한 번 더 `join`으로 감싸서, 최종적으로 "총 구매액이 가장 큰 고객 3명의 이름·연락처·국가·신용한도·총 구매액"을 한 번에 뽑아내는 쿼리가 완성됐다. 결과는 대략 아래와 같았다(스페인의 Euro+ Shopping Channel이 약 82만 달러로 1위).

### 파이썬 프로젝트 환경: `uv sync` vs `uv init`

- `pyproject.toml` 파일이 이미 존재할 때 → `uv sync`로 그 설정에 맞는 가상환경을 연결(설치)한다.
- 파일이 없을 때 → `uv init`으로 새 프로젝트 설정과 가상환경을 생성한다.

즉 이미 누군가 세팅해둔 프로젝트를 받아왔다면 `uv sync`, 완전히 처음부터 새로 시작한다면 `uv init`으로 생성한다.

### 커넥션 객체 생성하기

파이썬에서 MySQL에 접속하려면 아래 네 가지 정보가 필요하다.

- **Driver**: 파이썬에서 MySQL과 통신할 수 있게 해주는 라이브러리(여기서는 `pymysql`)
- **객체정보(ID, PW)**: 로그인할 계정과 비밀번호
- **MySQL 서버정보(IP, PORT)**: 접속할 서버 주소와 포트
- **데이터베이스명**: 접속해서 사용할 데이터베이스 이름

```python
import pymysql

DB_CONFIG = {
    # MySQL 서버정보
    "host": "localhost",
    "port": 3306,
    # 계정정보
    "user": "root",
    "password": "root1234",
    # 데이터베이스명
    "database": "classicmodels"
}
```

```python
# 커넥션 객체 생성
with pymysql.connect(**DB_CONFIG) as conn:
    # 커넥션 객체로 실행할 커서 생성
    with conn.cursor() as cur:
        # 해당 SQL 명령어를 MySQL 서버로 전달(실행)
        cur.execute("""
        show tables;
        """)
        # MySQL 결과 리턴
        results = cur.fetchall()

results  # 결과 확인
# (('customers',), ('employees',), ('offices',), ('orderdetails',),
#  ('orders',), ('payments',), ('productlines',), ('products',))
```

`with`문을 두 번 겹쳐 쓴 이유는, 커넥션(`conn`)과 커서(`cur`) 둘 다 "쓰고 나면 반드시 닫아줘야 하는 자원"이기 때문이다. `with`를 쓰면 블록이 끝날 때 자동으로 닫아주므로 실수로 연결을 안 끊는 상황을 방지할 수 있다.

### 비밀번호를 코드에 직접 쓰지 않기: `.env`와 `dotenv`

비밀번호나 계정 정보를 코드에 그대로 적어두면 깃허브 같은 곳에 실수로 올라갈 위험이 있다. 그래서 이런 값들은 `.env` 파일에 따로 적어두고, 코드에서는 `os.getenv()`로 불러오는 방식을 사용한다.

```python
import pymysql
import os  # 운영체제 환경변수 접근용

DB_CONFIG = {
    # MySQL 서버정보
    "host": os.getenv("host"),
    "port": int(os.getenv("port")),
    # 계정정보
    "user": os.getenv("user"),
    "password": os.getenv("password"),
    # 데이터베이스명
    "database": os.getenv("database")
}
```

다만 `os.getenv()`만으로는 `.env` 파일의 내용이 자동으로 환경변수에 등록되지 않는다. 이때 `python-dotenv` 라이브러리의 `load_dotenv()`를 먼저 실행해서 `.env` 파일 내용을 환경변수로 읽어들여야 한다.

```python
from dotenv import load_dotenv

# .env에 작성된 데이터를 환경변수로 등록
load_dotenv()   # True
```

`.env` 파일을 새로 만들거나 수정했다면, 노트북(커널)을 재시작(restart)해야 변경 사항이 반영된다는 점도 함께 기억해둘 부분이다.

### 커넥션을 재사용하기: 싱글톤으로 `connections.py` 만들기

매번 코드를 실행할 때마다 새로 커넥션을 맺는 대신, 한 번 만든 커넥션 객체를 계속 재사용하도록 싱글톤 패턴으로 `MySQLDB` 클래스를 만들었다.

```python
# connections.py
import pymysql

class Singleton(type):
    _instances = {}
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super(Singleton, cls).__call__(*args, **kwargs)
        return cls._instances[cls]

class MySQLDB(metaclass=Singleton):
    # 기억해야 할 변수 정의/설정
    # 기억해야 할 함수 -> 메소드에서 사용할 때 사용
    def __init__(self, DB_CONFIG: dict) -> None:
        # conn = 커넥션 객체
        self.conn = pymysql.connect(
            **DB_CONFIG,
            charset="utf8mb4",                     # 한글을 포함한 문자 인코딩 방식
            cursorclass=pymysql.cursors.DictCursor  # 결과를 딕셔너리 형태로 받기
        )

    def __call__(self, p_query: str) -> dict:
        # 커넥션 객체로 커서 생성
        with self.conn.cursor() as cur:
            # 해당 SQL 명령어를 MySQL 서버로 전달(실행)
            cur.execute(p_query)
            # MySQL 결과 리턴
            return cur.fetchall()
```

```python
# ex01.ipynb
from connections import MySQLDB

mysqldb = MySQLDB(DB_CONFIG)
```

이렇게 만들어두면, `mysqldb`는 프로그램 안에서 항상 같은 커넥션 인스턴스를 가리키게 되고, `mysqldb("select ...")`처럼 인스턴스를 함수처럼 호출(`__call__`)해서 바로 쿼리를 실행할 수 있다. 매번 `with pymysql.connect(...)`를 새로 쓰지 않아도 되니 코드가 훨씬 간결해진다.
