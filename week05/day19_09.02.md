## 1. Train/Test 데이터 분리

Test 데이터는 학습이 끝난 모델의 성능을 평가하는 시험지 역할을 한다. 따라서 Test 데이터의 정보를 전처리 기준 결정, Feature 선택, 모델 선택, 모델 학습에 사용하면 안 된다.

### 1.1 컬럼 확인과 중복 정보 제거

``` python
df.columns
df.columns[df.columns.duplicated()]

df.drop(
    ["class", "embark_town", "alive"],
    axis=1,
    inplace=True,
)
```

- `df.columns` → 전체 컬럼 이름 확인
- `df.columns.duplicated()` → 이름이 중복된 컬럼 확인
- `drop(..., axis=1)` → 컬럼 방향으로 제거

Titanic 실습에서는 같은 정보를 중복해서 표현하는 `class`, `embark_town`, `alive`를 제거해 `(891, 15)`에서 `(891, 12)`로 컬럼 수를 줄였다.

### 1.2 `train_test_split()`

``` python
from sklearn.model_selection import train_test_split

seed = 42

train, test = train_test_split(
    df,
    random_state=seed,
    test_size=0.2,
)

train.shape, test.shape
```

실행 결과:

``` text
((712, 12), (179, 12))
```

- `train_test_split()` → DataFrame의 행을 무작위로 나눔
- `test_size=0.2` → 전체 행의 20%를 Test로 사용
- `random_state=42` → 같은 분할 결과를 재현하도록 난수 기준을 고정

Test 비율은 고정된 정답이 아니라 전체 데이터 양과 평가에 필요한 Test 데이터 수를 고려해 정한다. 원본 필기에서는 예시로 약 1,000개 이상의 Test 데이터를 확보할 수 있을 때 8:2 분할, 데이터가 충분히 많은 다중분류에서는 7:3 분할을 언급했다.

> **핵심:** 분할한 뒤에는 Train을 분석해 처리 기준을 정하고 Test에는 같은 처리를 적용한다.

## 2. Train 중심 EDA

### 2.1 Target 분석

Target의 의미와 값의 종류를 확인해 문제 유형을 판단한다.

| Target의 특징 | 문제 유형 |
| --- | --- |
| 연속적인 수치 예측 | 회귀 |
| 범주 예측 | 분류 |
| 클래스 2개 | 이진분류 |
| 클래스 3개 이상 | 다중분류 |

숫자로 저장된 Target도 클래스 번호를 나타낼 수 있으므로 dtype만 보고 회귀로 판단하지 않는다. 분류에서는 각 클래스의 개수와 비율도 확인한다.

``` python
train["survived"].value_counts() / train.shape[0]
```

실행 결과:

``` text
0    0.623596
1    0.376404
```

### 2.2 수치형·범주형 데이터 분석

``` python
import numpy as np

train_number = train.select_dtypes(include=np.number)
train_str = train.select_dtypes(exclude=np.number)

train_number.describe()
train_str.describe()
```

수치형 데이터에서는 평균·표준편차·사분위수 등을, 범주형 데이터에서는 범주 수·최빈값·빈도 등을 확인한다.

### 2.3 Train과 Test의 결측치

Train과 Test는 서로 다른 행으로 구성되므로 결측치 개수와 비율이 다른 것이 정상이다.

``` python
(train.isnull().sum() / len(train)).sort_values(
    ascending=False
)

null_cols = (
    train.isnull().sum()[train.isnull().sum() > 0]
    .index
    .to_list()
)
```

- `ascending=False` → 내림차순 정렬
- `null_cols` → 결측치가 하나라도 있는 컬럼 이름만 리스트로 추출

결측치 대체값도 Train에서 정한 뒤 Test에 같은 기준을 적용해야 데이터 누수를 막을 수 있다.

## 3. Feature Engineering

Feature Engineering은 기존 컬럼을 조합하거나 변환해 모델이 학습할 새로운 Feature를 만드는 과정이다. 실습의 Feature Extraction은 새로운 변수를 생성해 컬럼 수를 늘리는 형태로 진행했다.

### 3.1 수치형 Feature 생성

``` python
train["family_cnt"] = train.apply(
    lambda row: int(row["sibsp"]) + int(row["parch"]),
    axis=1,
)

test["family_cnt"] = test.apply(
    lambda row: int(row["sibsp"]) + int(row["parch"]),
    axis=1,
)
```

`sibsp`와 `parch`를 더해 함께 탑승한 가족 수를 나타내는 `family_cnt`를 생성했다. Train의 Shape은 `(712, 12)`에서 `(712, 13)`으로 바뀌었다.

### 3.2 범주형 Feature 생성

``` python
train["deck"] = train["deck"].astype(str)
train["deck_who"] = train["deck"] + "_" + train["who"]

test["deck"] = test["deck"].astype(str)
test["deck_who"] = test["deck"] + "_" + test["who"]
```

`deck`와 `who`를 결합해 두 범주의 조합을 나타내는 `deck_who`를 만들었다. 같은 생성 규칙을 Train과 Test에 각각 적용해 두 데이터의 컬럼 구조를 맞춘다.

> **오류 수정:** 실습 원본은 `test["deck_who"]`를 만들 때 오른쪽에 `train["deck"]`과 `train["who"]`를 사용했다. 정리노트에서는 Test의 각 행으로 Test Feature를 생성하도록 수정했다.

원본 필기에서는 생성한 Feature 수가 행 수에 비해 지나치게 많지 않도록 확인하며, 일반적인 참고 범위로 행 수의 5% 미만을 언급했다.

## 4. 범주형 데이터 인코딩

인코딩은 문자열이나 범주형 값을 모델이 사용할 수 있는 수치 형태로 변환하는 과정이다.

### 4.1 순서형과 명목형

| 종류 | 의미 | 인코딩 시 고려점 |
| --- | --- | --- |
| 순서형(Ordinal) | 범주 사이에 순서가 있음 | 순서 정보를 보존할 수 있음 |
| 명목형(Nominal) | 범주 사이에 순서가 없음 | 임의의 크기 관계를 만들지 않아야 함 |

Ordinal Encoding은 순서가 있는 범주형 데이터에 사용하며, 순서가 없는 데이터에 임의로 적용하지 않는다.

### 4.2 One-Hot Encoding

One-Hot Encoding은 각 범주를 별도 컬럼으로 만들고 해당 여부를 `0`과 `1`로 표현한다.

``` text
범주형 벡터
  ↓ One-Hot Encoding
행 × 범주 컬럼의 행렬
```

- 장점 → 범주 사이에 거짓된 순서 관계를 만들지 않음
- 단점 → 범주 수만큼 컬럼이 늘어나 학습량과 시간이 증가할 수 있음
- 범주 수가 적을 때 우선 시도하고 평가 결과를 확인

### 4.3 Mean Encoding과 Target Encoding

Mean Encoding은 범주형 값을 **그 범주에 속한 Train 행들의 Target 평균값**으로 바꾸는 방법이다. 일반적으로 Target Encoding과 같은 의미로 사용한다.

| 지역 | 구매 여부(Target) |
| --- | ---: |
| 서울 | 1 |
| 서울 | 0 |
| 서울 | 1 |
| 부산 | 0 |
| 부산 | 0 |

``` text
서울 → (1 + 0 + 1) / 3 = 0.667
부산 → (0 + 0) / 2 = 0
```

따라서 `지역` 컬럼의 서울은 `0.667`, 부산은 `0`으로 변환된다. 여기서 사용하는 값은 전체 Target 평균이나 범주형 컬럼 자체의 평균이 아니라 **각 범주에 대응하는 Target 값의 평균**이다.

> **오류 수정:** 원본의 “타겟의 평균이 아님 자기 자신의 평균임”은 앞뒤 설명과 모순된다. 정확한 표현은 “각 범주에 해당하는 Target의 평균”이다.

Target 정보를 직접 사용하므로 다음을 주의한다.

- 평균은 Train 데이터에서만 계산한다.
- Test 데이터에는 Train에서 계산한 범주별 값을 적용한다.
- 범주별 데이터가 적으면 특정 Target에 지나치게 맞춰져 과적합될 수 있다.

> **핵심:** Mean/Target Encoding은 각 범주를 Train에서 구한 해당 범주의 Target 평균으로 변환한다.

## 5. 모델 학습과 평가 흐름

``` python
x_train = train.drop("target", axis=1)
y_train = train["target"]

x_test = test.drop("target", axis=1)
y_test = test["target"]
```

``` python
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

model = LogisticRegression(random_state=42)
model.fit(x_train, y_train)

y_pred = model.predict(x_test)
accuracy = accuracy_score(y_test, y_pred)
```

유방암 데이터 실습 결과 정확도는 다음과 같았다.

``` text
0.972027972027972
```

학습 과정에서는 반복 횟수 한도에 도달했다는 `ConvergenceWarning`이 발생했다. 출력 메시지는 반복 횟수 조정이나 데이터 스케일링을 검토하도록 안내했다.

### 5.1 하이퍼파라미터와 모델 파라미터

| 구분 | 결정 시점 | 결정 주체 |
| --- | --- | --- |
| 하이퍼파라미터 | 학습 전 | 사람이 설정하거나 탐색 |
| 모델 파라미터 | 학습 중 | 데이터로부터 결정 |

전체 머신러닝 과정은 다음과 같이 이어진다.

``` text
데이터 수집 → 전처리 → 모델 학습 → 평가
```

## 전체 흐름

``` text
데이터와 컬럼 구조 확인
  ↓
중복 정보를 가진 컬럼 제거
  ↓
Train / Test 행 분리
  ↓
Train 중심으로 Target·수치형·범주형·결측치 탐색
  ↓
Train에서 전처리와 Feature 생성 기준 결정
  ↓
Test에 같은 처리 적용
  ↓
Feature / Target 분리
  ↓
모델 학습
  ↓
Test 예측과 평가
```

| 개념 | 의미 |

| Train 데이터 | 전처리 기준과 모델을 학습하는 데이터 |

| Mean/Target Encoding | 범주를 Train에서 구한 해당 범주의 Target 평균으로 바꾸는 인코딩 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `train_test_split()` | 행 기준으로 Train과 Test 분리 |

| `sort_values(ascending=False)` | 내림차순 정렬 |

### ⭐ 오늘의 핵심

- **분리 우선:** Test 정보를 EDA·전처리 기준·Feature 선택·모델 선택에 사용하지 않는다.
- **일관된 처리:** Train에서 정한 처리와 Feature 생성 규칙을 Test에도 동일하게 적용한다.
- **문제 유형:** Target의 dtype만이 아니라 값의 의미와 클래스 수로 회귀·이진분류·다중분류를 판단한다.
- **Feature 생성:** 기존 수치형·범주형 컬럼을 조합해 학습에 유용한 새 정보를 만들 수 있다.
- **인코딩 선택:** 범주에 순서가 있는지와 범주 수를 고려해 인코딩 방법을 선택한다.
