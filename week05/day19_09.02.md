## 2. 머신러닝의 전체 과정

머신러닝은 데이터를 바로 모델에 넣는 것이 아니라 수집, 탐색, 전처리, 학습, 평가 과정을 거친다.

```text
데이터 수집
  ↓
데이터 분할
  ↓
학습 데이터 EDA
  ↓
전처리·피처 추출·인코딩
  ↓
모델 학습
  ↓
테스트 데이터로 최종 평가
```

### 2.1 고정 설정값 관리

```python
import easydict

args = easydict.EasyDict()

args.seed = 42
args.target_col = 'target'
```

- `seed` → 무작위 결과를 동일하게 재현하기 위한 값
    
- `target_col` → 예측하려는 타겟 컬럼의 이름
    

`random_state`를 같은 값으로 지정하면 데이터를 다시 분할해도 같은 결과를 얻을 수 있다.

## 3. 데이터 누수와 학습·테스트 데이터 분할

데이터 누수(data leakage)는 모델이 학습할 때 알면 안 되는 테스트 데이터나 정답 정보를 미리 사용하는 문제이다. 데이터 누수가 발생하면 평가 점수는 높아 보여도 새로운 데이터에서는 성능이 떨어질 수 있다.

> **핵심:** 테스트 데이터를 모델 학습, 전처리 기준 결정, 피처 선택, 모델 선택에 사용하면 안 된다.

### 3.1 중복·유사 컬럼 확인

```python
df.columns
```

`df.columns`는 전체 컬럼 이름을 확인한다. 컬럼 이름 자체가 중복되었는지는 다음 코드로 확인한다.

```python
df.columns[df.columns.duplicated()]
```

Titanic 데이터의 다음 컬럼들은 값의 표현은 다르지만 의미가 서로 겹친다.

| 기존 컬럼 | 의미가 겹치는 컬럼 |
| --- | --- |
| `pclass` | `class` |
| `embarked` | `embark_town` |
| `survived` | `alive` |

```python
df.drop(
    ['class', 'embark_town', 'alive'],
    axis=1,
    inplace=True
)
```

이 컬럼들은 **컬럼명 자체가 중복된 것이 아니라 의미가 중복되거나 유사한 컬럼**이다.

### 3.2 행을 기준으로 데이터 분할

```python
from sklearn.model_selection import train_test_split

seed = 42

train, test = train_test_split(
    df,
    test_size=0.2,
    random_state=seed,
    stratify=df['survived']
)

train.shape, test.shape
```

- `train_test_split()` → DataFrame의 행을 학습용과 테스트용으로 분할
    
- `test_size=0.2` → 전체 데이터 중 20%를 테스트 데이터로 사용
    
- `random_state=42` → 같은 분할 결과가 나오도록 고정
    
- `stratify=df['survived']` → train과 test의 클래스 비율을 비슷하게 유지
    

Titanic 데이터 891개를 8:2로 나누면 다음과 같다.

```text
train: 712행
test:  179행
```

### 3.3 데이터 분할 비율

`8:2`, `7:3`은 자주 사용하는 비율이지만 절대적인 규칙은 아니다.

- 데이터가 적음 → 학습 데이터를 충분히 확보하고 교차검증 사용 고려
    
- 데이터가 많음 → 작은 테스트 비율만으로도 충분한 평가 데이터 확보 가능
    
- 분류 문제 → 전체 개수뿐 아니라 클래스별 데이터 수와 비율 확인
    

테스트 데이터가 반드시 1,000개 이상이어야 하거나, 다중분류의 `7:3` 분할에 반드시 10,000개 이상이 필요하다는 규칙은 없다. 문제의 난이도, 클래스 수, 클래스 불균형, 평가 지표에 따라 결정한다.

### 3.4 안전한 EDA와 전처리 순서

분할 후에는 `train`을 중심으로 EDA를 진행하고 전처리 기준을 정한다. 이후 같은 기준을 `test`에 적용한다.

```text
전체 데이터 분할
  ↓
train으로 EDA와 전처리 기준 결정
  ↓
train에 전처리 적용
  ↓
같은 기준을 test에 적용
  ↓
최종 평가 시 test 사용
```

테스트 데이터의 컬럼 구조를 확인하는 것 자체가 금지되는 것은 아니다. 다만 테스트 데이터의 분포나 평가 결과를 반복해서 보며 모델을 수정하면 테스트 데이터에 과적합될 수 있다.

## 4. 타겟 데이터 분석

타겟(target)은 모델이 예측하려는 값이다. 모델 종류는 타겟의 저장 타입이 아니라 **값의 의미**를 기준으로 결정한다.

### 4.1 회귀와 분류

| 타겟의 의미 | 문제 유형 | 예시 |
| --- | --- | --- |
| 연속적인 수치 예측 | 회귀 | 집값, 온도, 매출액 |
| 정해진 범주 예측 | 분류 | 생존 여부, 암 종류, 상품 등급 |

숫자로 저장된 타겟도 범주를 나타내면 분류 문제이다.

```text
survived = 0 또는 1
```

`0`과 `1`은 연속적인 수치가 아니라 사망과 생존이라는 범주를 뜻하므로 이진분류이다.

### 4.2 이진분류와 다중분류

- `클래스 2개` → 이진분류
    
- `클래스 3개 이상` → 다중분류
    

```python
train['survived'].nunique()
train['survived'].value_counts()
train['survived'].value_counts(normalize=True)
```

Titanic 학습 데이터의 클래스 비율은 실행 결과에 따라 약 다음과 같다.

```text
사망(0): 약 62%
생존(1): 약 38%
```

클래스 비율 차이가 크면 모델이 데이터가 많은 클래스만 잘 예측할 수 있으므로 반드시 분포를 확인한다.

## 5. 하이퍼파라미터와 모델 파라미터

### 5.1 하이퍼파라미터

하이퍼파라미터(hyperparameter)는 학습 전에 사람이 설정하거나 탐색하는 값이다.

```python
model = LogisticRegression(
    random_state=42,
    max_iter=1000
)
```

`max_iter`와 `random_state` 등이 하이퍼파라미터에 해당한다. 사람이 직접 정할 수도 있고 탐색 도구로 자동 탐색할 수도 있다.

### 5.2 모델 파라미터

모델 파라미터(model parameter)는 모델이 학습 데이터에서 스스로 학습하는 값이다.

- 가중치(weight)
    
- 편향(bias)
    
- 회귀계수(coefficient)
    

일반적으로 개발자가 값을 직접 정하지는 않지만, 학습 방법과 하이퍼파라미터를 통해 간접적으로 영향을 줄 수 있다.

> **핵심:** 사람이 학습 전에 설정하는 값은 하이퍼파라미터, 모델이 학습 과정에서 결정하는 값은 모델 파라미터이다.

수치형과 범주형 데이터는 적용하는 전처리 방법이 다르므로 분리하여 처리한다.

```python
import numpy as np

x_train_number = x_train.select_dtypes(include=np.number)
x_train_str = x_train.select_dtypes(exclude=np.number)

x_test_number = x_test.select_dtypes(include=np.number)
```

```text
x_train

x_test
├─ x_test_number: 숫자형 컬럼
```

`x_train_str`에는 문자열뿐 아니라 `category`, `bool`처럼 숫자가 아닌 타입도 들어갈 수 있다. 따라서 `x_train_category`와 같은 이름이 더 정확할 수 있다.

```python
len(x_train.columns) == (
```

## 7. 결측치 확인과 처리

### 7.1 결측치가 있는 컬럼 추출

```python
null_cols = (
    df_tmp.isnull().sum()
    [df_tmp.isnull().sum() > 0]
    .index.to_list()
)
```

코드의 실행 순서는 다음과 같다.

```text
컬럼별 결측치 수 계산
  ↓
결측치 수가 0보다 큰 컬럼만 선택
  ↓
선택된 컬럼의 이름 추출
  ↓
리스트로 변환
```

결과적으로 **결측치가 하나라도 있는 컬럼 이름만 리스트로 추출**한다.

### 7.2 결측치 비율 정렬

```python
missing_ratio = (
    train.isnull().sum() / len(train)
).sort_values(ascending=False)
```

Pandas에서는 내림차순 정렬을 다음과 같이 표현한다.

```python
sort_values(ascending=False)
```

- `ascending=True` → 오름차순
    
- `ascending=False` → 내림차순
    

train과 test는 서로 다른 행으로 구성되므로 결측치의 개수와 비율이 다른 것이 정상이다.

### 7.3 데이터 누수를 방지한 결측치 처리

결측치 대체값은 **train에서만 계산**하고 같은 값을 test에 적용해야 한다.

```python
import pandas as pd

for col in train.columns:
    if not train[col].isnull().any():
        continue

    if pd.api.types.is_numeric_dtype(train[col]):
        fill_value = train[col].median()
    else:
        fill_value = train[col].mode().iloc[0]

    train[col] = train[col].fillna(fill_value)
    test[col] = test[col].fillna(fill_value)
```

- 수치형 컬럼 → train의 중앙값으로 대체
    
- 범주형 컬럼 → train의 최빈값으로 대체
    

train과 test에서 각각 평균이나 최빈값을 계산하면 test의 정보가 전처리 기준에 사용되므로 데이터 누수가 발생한다.

```python
train.isnull().sum().sum(), test.isnull().sum().sum()
```

전처리 후에는 결측치가 모두 처리되었는지 반드시 검증한다.

> **핵심:** train과 test의 결측치 상태는 달라도 되지만, 전처리 기준은 반드시 train에서 구해 동일하게 적용한다.

## 8. 피처 추출

피처 추출(feature extraction)은 기존 데이터를 조합하거나 변환하여 모델 학습에 도움이 되는 새로운 변수를 만드는 과정이다.

### 8.1 수치형 피처 생성

Titanic 데이터의 형제·배우자 수와 부모·자녀 수를 더해 가족 수를 만든다.

```python
train['family_cnt'] = (
    train['sibsp'].astype(int)
    + train['parch'].astype(int)
)

test['family_cnt'] = (
    test['sibsp'].astype(int)
    + test['parch'].astype(int)
)
```

노트북의 `apply(..., axis=1)`도 사용할 수 있지만, 단순한 컬럼 연산은 위와 같이 벡터 연산으로 처리하는 것이 더 간단하고 빠르다.

### 8.2 범주형 피처 생성

`deck`과 `who`를 조합해 새로운 범주형 피처를 만든다.

```python
train['deck'] = train['deck'].astype(str)
test['deck'] = test['deck'].astype(str)

train['deck_who'] = train['deck'] + '_' + train['who']
test['deck_who'] = test['deck'] + '_' + test['who']
```

test의 피처를 만들 때는 반드시 test 컬럼끼리 조합해야 한다.

### 8.3 피처 개수에 관한 주의점

피처가 늘어나면 더 많은 정보를 표현할 수 있지만 다음 문제가 생길 수 있다.

- 학습 시간과 메모리 사용량 증가
    
- 불필요한 피처로 인한 과적합
    
- 차원의 저주
    

컬럼 수를 행 수의 5% 미만으로 제한해야 한다는 것은 절대적인 규칙이 아니라 참고용 경험칙이다. 데이터의 양, 모델 종류, 피처의 품질을 함께 고려해야 한다.

## 9. 데이터 인코딩

데이터 인코딩(data encoding)은 문자열이나 범주형 데이터를 모델이 계산할 수 있는 숫자 형태로 변환하는 과정이다. 인코딩 방법은 여러 가지이며 데이터 특성과 모델에 맞게 선택한다.

### 9.1 One-Hot Encoding

원-핫 인코딩(One-Hot Encoding)은 각 범주를 별도의 컬럼으로 만들고 해당 여부를 0과 1로 표시한다.

```text
sex
male
female

       ↓ One-Hot Encoding

sex_male  sex_female
    1          0
    0          1
```

하나의 범주형 벡터가 여러 컬럼을 가진 행렬로 변환된다.

```python
import category_encoders as ce

encoder = ce.OneHotEncoder(use_cat_names=True)

encoder.fit(x_train_str)

x_train_enc = encoder.transform(x_train_str)
x_test_enc = encoder.transform(x_test_str)
```

- `fit()` → train에서 범주의 종류와 변환 기준 학습
    
- `transform()` → 학습한 기준으로 train과 test 변환
    
- `use_cat_names=True` → 생성된 컬럼 이름에 실제 범주 이름 사용
    

One-Hot Encoding 후 수치형 피처와 합친다.

```python
x_train_final = pd.concat(
    [x_train_number, x_train_enc],
    axis=1
)

x_test_final = pd.concat(
    [x_test_number, x_test_enc],
    axis=1
)
```

#### 장점

- 범주에 임의의 크기나 순서를 만들지 않음
    
- 범주의 개수가 적은 명목형 데이터에 적합
    
- 간단하고 널리 사용하는 기본 방법
    

#### 단점

- 범주의 종류만큼 컬럼이 증가
    
- 0이 많은 희소 데이터가 생성
    
- 범주가 많으면 학습 시간과 메모리 사용량이 증가
    
- 범주 사이의 유사성을 직접 표현하지 못함
    

One-Hot Encoding이 항상 평가 점수를 떨어뜨리는 것은 아니다. 범주 수가 적을 때 먼저 시도하기 좋은 기본 방법이며, 범주 수가 많아 차원이 지나치게 커질 때 다른 방법과 비교한다.

### 9.2 Ordinal Encoding

오디널 인코딩(Ordinal Encoding)은 순서가 있는 범주를 순서에 맞는 숫자로 변환한다.

```text
낮음 → 0
보통 → 1
높음 → 2
```

등급, 만족도, 크기처럼 순서가 있는 데이터에 사용한다. 서울, 부산, 제주처럼 순서가 없는 데이터에 사용하면 모델이 잘못된 크기 관계를 학습할 수 있다.

### 9.3 Frequency Encoding

빈도 인코딩(Frequency Encoding)은 각 범주를 그 범주의 등장 비율로 변환한다.

```text
male이 전체의 65%   → 0.65
female이 전체의 35% → 0.35
```

타겟을 사용하지 않으면서 One-Hot Encoding보다 컬럼 수를 적게 유지할 수 있다. 빈도 기준도 train에서 계산하고 test에 적용한다.

### 9.4 Mean Encoding과 Target Encoding

평균 인코딩(Mean Encoding)은 보통 타겟 인코딩(Target Encoding)과 같은 의미로 사용한다. 각 범주를 해당 범주의 **타겟 평균값**으로 바꾼다.

```text
남성 승객의 평균 생존율 → male을 해당 값으로 변환
여성 승객의 평균 생존율 → female을 해당 값으로 변환
```

```python
target_mean = train.groupby('sex')['survived'].mean()

train['sex_target'] = train['sex'].map(target_mean)
test['sex_target'] = test['sex'].map(target_mean)
```

Mean Encoding이 자기 자신의 평균을 구하는 별도의 방법이라는 설명은 정확하지 않다. 일반적으로 범주별 타겟 평균을 사용하기 때문에 Target Encoding과 같은 뜻이다.

#### 장점

- 범주가 많아도 컬럼이 크게 증가하지 않음
    
- 타겟과 범주의 관계를 하나의 숫자로 표현
    

#### 단점

- 타겟을 사용하므로 데이터 누수가 발생하기 쉬움
    
- 데이터가 적은 범주에서 과적합이 발생하기 쉬움
    

안전하게 사용하려면 교차검증 기반 인코딩, 스무딩 등의 방법을 사용해야 한다.

### 9.5 인코딩 방법 비교

| 인코딩 | 변환 기준 | 적합한 데이터 | 주요 주의점 |
| --- | --- | --- | --- |
| One-Hot Encoding | 범주마다 컬럼 생성 | 순서가 없고 범주 수가 적음 | 컬럼 수 증가 |
| Ordinal Encoding | 범주의 순서 | 순서가 있는 범주 | 순서 없는 범주에 사용 금지 |
| Frequency Encoding | 범주의 등장 비율 | 범주 수가 많음 | 서로 다른 범주의 빈도가 같을 수 있음 |
| Target·Mean Encoding | 범주별 타겟 평균 | 범주 수가 많고 타겟과 관계가 있음 | 누수와 과적합 주의 |
| Binary Encoding | 범주 번호를 이진수로 표현 | 범주 수가 많음 | 해석이 어려울 수 있음 |

인코딩 방법이 반드시 최소 5개로 정해진 것은 아니며, 이 밖에도 Hash Encoding, Embedding 등 다양한 방법이 있다.

## 10. 모델 학습과 평가

피처와 타겟을 분리한 뒤 train으로 모델을 학습하고 test로 최종 성능을 평가한다.

```python
x_train = train.drop('survived', axis=1)
y_train = train['survived']

x_test = test.drop('survived', axis=1)
y_test = test['survived']
```

```python
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

model = LogisticRegression(
    random_state=42,
    max_iter=1000
)

model.fit(x_train_final, y_train)

y_pred = model.predict(x_test_final)
accuracy = accuracy_score(y_test, y_pred)
```

- `fit()` → 학습 피처와 정답을 이용해 모델 파라미터 학습
    
- `predict()` → 테스트 피처의 결과 예측
    
- `accuracy_score()` → 실제 정답과 예측값을 비교해 정확도 계산
    

로지스틱 회귀에서 반복 횟수 부족 경고가 발생하면 `max_iter`를 늘리거나 수치형 데이터의 스케일링을 고려한다.

### 💻 주요 코드

| 코드 | 의미 |

### ⭐ 오늘의 핵심

- **데이터를 먼저 train과 test로 분할하고, EDA와 전처리 기준은 train으로 결정한다.**
    
- **타겟이 숫자인지만 보지 말고 값의 의미를 기준으로 회귀와 분류를 판단한다.**
    
- **결측치 대체와 인코딩 기준은 train에서 학습한 뒤 test에 동일하게 적용한다.**
    
- **One-Hot Encoding은 범주 수가 적을 때 좋은 기본 방법이지만 범주 수만큼 컬럼이 증가한다.**
    
- **Mean Encoding과 Target Encoding은 일반적으로 같은 의미이며 누수와 과적합에 주의한다.**
