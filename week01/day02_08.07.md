## 2. Git의 세 가지 저장 공간

Git은 파일의 상태를 세 공간으로 나누어 관리한다.

### 2.1 Working Directory

실제 프로젝트 파일을 수정하거나 새 파일을 만드는 작업 공간이다. 파일을 변경하면 `Modified` 상태가 된다. `.git` 폴더가 포함된 프로젝트 전체를 Git 저장소라고 한다.

### 2.2 Staging Area

커밋할 파일을 임시로 모아 두는 공간이다.

- `Changes` → 변경되었지만 아직 Stage하지 않은 파일
- `Staged Changes` → 다음 Commit에 포함할 파일

### 2.3 Repository

Commit된 변경 이력이 `.git` 디렉터리에 저장되는 공간이다. 파일은 Commit 후 `Committed` 상태가 된다.

``` text
Working Directory (Modified)
  ↓ git add
Staging Area (Staged)
  ↓ git commit
Repository (.git, Committed)
```

> **핵심:** `git add`는 커밋 대상을 고르고, `git commit`은 선택한 변경 내용을 로컬 저장소의 이력으로 남긴다.

## 3. Git Graph와 원격 저장소 동기화

Git Graph에서 Commit 기록을 그래프로 확인할 수 있다. 그래프의 원 표시는 Commit된 상태를 나타내며, 수업에서는 Git Graph의 `New` 기능도 확인했다.

`origin`은 GitHub의 원격 저장소를 가리키는 기본 이름이다. 브랜치 이름 뒤에 `origin`이 표시되면 원격 저장소와 연결된 상태를 확인할 수 있다.

- `Git` → 로컬 컴퓨터에서 변경 이력을 관리
- `GitHub` → 원격 저장소를 제공하는 서비스
- `push` → 로컬 Git의 Commit을 GitHub에 업로드
- `pull` → GitHub의 변경 내용을 로컬 Git으로 내려받기

수업에서는 기본 작업 순서를 `pull` 후 `push`로 정리했다.

``` text
GitHub의 변경 내용
  ↓ pull
로컬 Git
  ↓ push
GitHub에 로컬 Commit 반영
```

## 4. Branch와 Merge

Branch는 여러 개발자가 동시에 서로 다른 작업을 진행할 수 있게 해 주며, Merge는 나뉜 작업을 하나로 합치는 과정이다.

### 4.1 브랜치 역할

| 브랜치 | 역할 |
| --- | --- |
| `main` | 서비스 배포에 사용하는 안정된 코드 관리 |
| `develop` | feature에서 개발한 내용을 합치고 테스트 |
| `feature` | 기능별 개발 작업 수행 |
| `release` | 배포 전 실제 데이터로 QA 및 배포 테스트 |
| `hotfix` | 운영 중 발생한 오류를 빠르게 수정 |

### 4.2 브랜치 작업 흐름

``` text
main
  ↓ develop 생성
develop
  ↓ feature 생성
feature에서 기능 개발
  ↓ Merge
develop에서 통합·테스트
  ↓ release에서 배포 전 테스트
main에 반영
```

운영 중 오류가 발생하면 다음 흐름으로 처리한다.

``` text
main → hotfix → 수정 → Merge
```

VSCode의 브랜치 메뉴에서 새 브랜치를 만들 수 있다. 수업에서는 GitHub의 원격 브랜치인 `origin` 브랜치를 기준으로 선택하고, `develop`에서 `feature`를 대상으로 Merge하는 화면을 확인했다. 개발이 끝난 feature 브랜치는 삭제하고 `develop`, `main` 브랜치를 남긴다.

GitHub 저장소 자체를 삭제하려면 저장소의 `Settings → Delete this repository`를 사용한다.

## 5. pip와 venv를 이용한 가상환경

프로젝트마다 필요한 라이브러리를 분리하기 위해 Python 가상환경을 만든다. VSCode는 프로젝트 폴더 단위로 열고, 수업에서는 저장소 하나를 프로젝트 하나로 구성했다.

`venv1` 폴더에 `requirements.txt`를 만들고 다음 패키지 이름을 작성했다.

``` text
jupyter
pandas
seaborn
```

`#`은 컴퓨터가 실행하지 않는 주석을 표시할 때 사용한다.

``` powershell
py --version
py -m venv .venv
.\.venv\Scripts\activate
py -m pip install --upgrade pip
pip install -r .\requirements.txt
deactivate
```

- `py -m venv .venv` → `.venv`라는 가상환경 생성
- `.\.venv\Scripts\activate` → Windows PowerShell에서 가상환경 활성화
- `py -m pip install --upgrade pip` → pip 업그레이드
- `pip install -r .\requirements.txt` → 파일에 적힌 패키지 설치
- `deactivate` → 가상환경 비활성화
- `Lib` → 설치된 라이브러리가 들어가는 폴더
- `Scripts` → `activate` 등 실행 파일이 들어가는 폴더

> **오류 수정:** 원본의 `-m = 관리자 모드` 설명은 잘못되었다. `-m`은 Python 모듈을 스크립트처럼 실행하는 옵션이다.

## 6. uv를 이용한 가상환경

`venv2` 폴더에서 uv 프로젝트를 초기화하고 패키지를 추가했다.

``` powershell
uv init --name venv-uv --python 3.12
uv add jupyter pandas seaborn
.\.venv\Scripts\activate
deactivate
uv sync
```

- `uv init --name venv-uv --python 3.12` → Python 3.12를 사용하는 `venv-uv` 프로젝트 초기화
- `uv add jupyter pandas seaborn` → 패키지를 프로젝트 의존성으로 추가
- `pyproject.toml` → `jupyter`, `pandas`, `seaborn` 의존성 확인
- `uv sync` → 프로젝트 설정에 맞게 가상환경과 의존성을 동기화

수업의 `add = install` 표현은 패키지를 사용할 수 있게 설치한다는 흐름을 설명한 것이다. uv에서 `add`는 패키지를 설치하면서 프로젝트 의존성에도 등록한다.

## 7. Jupyter Notebook과 변수·상수

### 7.1 Jupyter Notebook 실행

Jupyter Notebook 파일의 확장자는 `.ipynb`이다. VSCode에 Jupyter 확장을 설치하고 `test.ipynb`를 만든 뒤 실행할 Kernel을 선택한다. 셀은 `Shift+Enter`로 실행한다.

실행이 정상적으로 다시 시작되지 않으면 `Ctrl+Shift+P`에서 `Python Debugger: Clear Cache and Reload Window`를 실행해 창을 다시 불러온다.

실습의 Python 파일에서는 다음 코드를 실행했다.

``` python
import pandas as pd
import seaborn as sns

print("Hello World")
```

실행 결과:

``` text
Hello World
```

### 7.2 변수

변수는 값을 저장하는 이름이며, 저장된 값을 다른 값으로 변경할 수 있다.

``` python
name = "홍길동"
name
```

실행 결과:

``` text
'홍길동'
```

``` python
name = "신사임당"
name
```

실행 결과:

``` text
'신사임당'
```

### 7.3 상수와 Enum

Python에서는 변경하지 않을 값의 이름을 관례적으로 대문자로 작성한다. 하지만 대문자로 작성하는 것만으로 값 변경이 막히지는 않는다.

``` python
PI = 3.14
PI = "홍길동"
PI
```

실행 결과:

``` text
'홍길동'
```

`enum.Enum`을 사용하면 관련된 상수 값을 하나의 집합으로 만들 수 있다.

``` python
import enum

class RAINBOW(enum.Enum):
    RED = "빨강"
    ORANGE = "주황"
    YELLOW = "노랑"
    GREEN = "초록"
    BLUE = "파랑"
    NAVY = "남색"
    PURPLE = "보라"

RAINBOW.RED.value
```

실행 결과:

``` text
'빨강'
```

다음처럼 Enum 멤버의 값을 바꾸려고 하면 오류가 발생한다.

``` python
RAINBOW.RED.value = "블랙"
```

실행 결과:

``` text
AttributeError: <enum 'Enum'> cannot set attribute 'value'
```
